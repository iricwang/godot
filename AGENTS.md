# AGENTS.md

Godot Engine 4.7-beta fork, branch `feature/game_framework`. Adds custom C++ modules (`enhanced_input`, `game_framework`, `interactive_music`, `objectdb_profiler`) and a `plinko_game/` demo project that exercises the new modules.

## Setup commands

- Python: 3.9+ (SCons requirement; SConstruct pins `EnsurePythonVersion(3, 9)`)
- Generate VS solution: `gen_sln.bat` (Windows) — produces `compile_commands.json` for clangd/clang-tidy
- Build editor (Windows): `python -m SCons platform=windows target=editor dev_build=yes -j%NUMBER_OF_PROCESSORS%`
- Build release: `python -m SCons platform=windows target=release_debug -j%NUMBER_OF_PROCESSORS%`
- Run the plinko_game demo: `bin\godot.windows.editor.dev.x86_64.exe --path plinko_game`
- Run headless smoke test: `bin\godot.windows.editor.dev.x86_64.exe --headless --path plinko_game -s verify_demo.gd`
- Format C++: `pre-commit run clang-format --files <path>` (or run all: `pre-commit run --all-files`)
- Lint C++ (manual stage, requires fresh `compile_commands.json`): `pre-commit run --hook-stage manual clang-tidy --files <path>`

## Project layout

- `core/`, `main/`, `scene/`, `servers/`, `editor/`, `drivers/`, `platform/` — upstream Godot 4.7 engine (C++)
- `modules/` — engine modules; custom additions on this branch: `enhanced_input/`, `game_framework/`, `interactive_music/`, `objectdb_profiler/`
- `modules/<name>/doc_classes/*.xml` — ClassDB doc, regenerated by `doc/classes/` build step
- `tests/` — engine unit tests; `tests/compatibility_test/` runs the `master` suite
- `plinko_game/` — Godot demo project (smoke test for `enhanced_input`); has its own `project.godot` and `verify_demo.gd`
- `openspec/specs/` — OpenSpec specifications (proposed changes live in `openspec/changes/`)
- `thirdparty/` — vendored dependencies; ignored by clang-tidy and pre-commit
- `bin/`, `obj/`, `.sconsign5.dblite`, `.scons_env.json` — build outputs (gitignored)

## Code style

- C++: `.clang-format` at repo root (Godot upstream style — 4-space indent, 120-col soft limit, braces on new line for functions, K&R-ish for control flow). Honor it; do not hand-format.
- C++ headers: `#pragma once` is the standard (see existing `core/`, `scene/`)
- GDScript: snake_case files, tabs for indent, type hints preferred (`var x: int = 0`). Match the style in `plinko_game/`.
- Module register: every new module needs `register_module_types.{h,cpp}` plus a `SCsub` and an entry in `modules/modules_builders.py`
- New public C++ classes: add a `doc_classes/ClassName.xml` next to the source (see `modules/game_framework/doc_classes/Activity.xml` for the schema)
- GDExtension API surface: keep the C++ class minimal; expose only the methods that GDScript actually needs

## Testing instructions

- Engine unit tests: `python -m SCons platform=windows target=editor tests=yes -j%NUMBER_OF_PROCESSORS% && bin\godot.windows.editor.dev.x86_64.exe --test --test-suite="[Core]"`
- Module tests live under `modules/<name>/tests/` (gated by `tests=yes` in the SCons invocation)
- `plinko_game/verify_demo.gd` must end with `=== ALL ASSERTIONS PASSED ===`
- Manual smoke test of the game: run editor, load `plinko_game/scenes/plinko_demo.tscn`, click each of the 5 buttons, confirm the status label updates
- Add tests for every new behavior — prefer extending the engine test suite for module C++ and a new `verify_*.gd` script for plinko_game changes

## PR & commit conventions

- Default branch: `master` (engine) and `feature/game_framework` (active work). Never push to `master` directly.
- Branch from `feature/game_framework` for module work; from `master` for engine-upstream sync.
- Commit messages: conventional commits (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`). When changing a custom module, prefix with the module name: `feat(enhanced_input): ...`
- Re-merge `upstream/4.7` before opening a PR — see `git log` for the `Merge remote-tracking branch 'upstream/4.7'` pattern
- Open PR via `gh pr create` once local SCons build + the relevant `--test` suite pass

## Security

- `.env` and platform-specific secrets are not tracked; do not commit them.
- `compile_commands.json` is gitignored — regenerate with `gen_sln.bat` after any SConstruct change.
- The `screenshot-auto` / `bin/screenshot-auto.exe` is a local dev tool, not part of the engine — do not rely on it in CI.

## Notes for AI agents

- This is a **forked engine**, not a Godot project. Do not run `godot --path .` at the repo root — only `plinko_game/` is a runnable project.
- The custom modules in `modules/enhanced_input/`, `modules/game_framework/`, `modules/interactive_music/`, `modules/objectdb_profiler/` are the focus of the current branch. The user has per-module design notes (see `modules/<name>/PROGRESS.md` when present).
- OpenSpec specs in `openspec/specs/` describe upcoming work; check there before assuming a module's intended API.
- For Plinko-related work, see `plinko_game/README.md` — it documents the IMC stack and the `enhanced_input` smoke-test contract.
